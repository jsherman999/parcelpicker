How to read this:
  • ✅ PASS — the browser completed the cross-origin request. This endpoint works in an all-in-browser build from this origin.
  • ❌ FAIL — the fetch was rejected. Browsers report CORS blocks and network errors identically as TypeError: Failed to fetch / Load failed. Open DevTools → Console for the precise reason: a line with "blocked by CORS policy" = CORS; otherwise a network error.
  • LLM rows: getting any HTTP status back — even 401/403 from an invalid key — means CORS passed (the browser could only read the response because the server allowed it). A bad-key 401 is a ✅ for our purposes; only a rejected fetch is a CORS/network ❌.
Origin matters: some servers only allow specific origins. For a trustworthy result, serve this from the origin you intend to deploy to. Avoid file:// — its origin is null and behaves differently.
